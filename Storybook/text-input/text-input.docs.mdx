# TextInput

A single-line text field built on a native `<input>`. It is designed to compose with `iris-form-field`, `iris-label`, and `iris-subtext`, but it can also be used standalone when label and feedback are handled elsewhere.

Current implementation supports visual size, disabled / readonly state, and decorative leading / trailing icons. It does not expose a `type` input, so rendered native input behaves as default text input only.

## Validation error

Connect input to reactive form control. Error styling appears only when bound control is both invalid and touched. `iris-form-field` shows first matching `iris-subtext type="error"` and hides hint text.

```html
<iris-form-field>
  <iris-label>Email</iris-label>
  <iris-text-input [formControl]="emailControl" placeholder="you@example.com"></iris-text-input>
  <iris-subtext type="hint">Enter your work email address.</iris-subtext>
  @if (emailControl.hasError('required')) {
    <iris-subtext type="error">Email is required.</iris-subtext>
  }
  @if (emailControl.hasError('email')) {
    <iris-subtext type="error">Enter a valid email address.</iris-subtext>
  }
</iris-form-field>
```

## Accessibility

- `iris-label` provides label association when composed inside `iris-form-field`.
- Native text-input keyboard behavior is preserved; component adds no custom shortcuts.
- `aria-invalid` is set only when attached form control exists and is both invalid and touched.
- Required state comes from `Validators.required` on bound form control; there is no separate `required` input.
- Readonly inputs stay focusable. Disabled inputs do not.
